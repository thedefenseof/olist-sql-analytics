
### power-bi/
Дашборд из 6 страниц:
1. **Обложка** — контекст проекта, ключевые цифры, навигация
2. **Обзор** — динамика выручки, топ категорий, общая картина бизнеса
3. **Доставка и отзывы** — зависимость оценки заказа от задержки доставки, топ проблемных штатов
4. **Продавцы и товары** — топ продавцов, надёжность (% опозданий), стоимость доставки по категориям
5. **Сегментация клиентов** — RFM-анализ, распределение по сегментам
6. **Выводы и рекомендации** — итоговые бизнес-инсайты

Построено на модели данных типа «звезда» (8 таблиц), свыше 20 DAX-мер.

### sql/queries.sql
5 запросов, дублирующих ключевую аналитику из дашборда на чистом SQL:
1. Топ-10 продавцов по выручке — оконная функция `RANK()`
2. Динамика выручки по месяцам со скользящим средним за 3 месяца — `AVG() OVER`, CTE
3. Зависимость оценки заказа от задержки доставки — `JOIN`, `CASE`, агрегация
4. Топ-10 категорий по выручке с долей от общей суммы — `CTE`, `SUM() OVER`
5. RFM-сегментация клиентской базы — тройной `CTE`, `JOIN`, `EXTRACT`, `CASE`

### python/load_to_postgres.py
Загружает 9 CSV-файлов датасета в PostgreSQL через pandas + SQLAlchemy (простой ETL-скрипт: чтение → запись в таблицы).

## Ключевые инсайты

- **Доставка — главный фактор недовольства.** Опоздание свыше 7 дней снижает среднюю оценку заказа с 4.25★ до 1.7★. Под риском — 7.9% заказов (~8 тыс., 1.35 млн выручки), сконцентрированных в нескольких штатах.
- **Низкий retention.** Только 3.12% клиентов совершают повторную покупку; 58% относятся к «спящему» сегменту.
- **VIP-сегмент непропорционально ценен.** 3.6% клиентов формируют 6.94% выручки.
- **Здоровая диверсификация продавцов.** Топ-10 продавцов дают лишь ~11% выручки, при этом демонстрируют минимальный % опозданий — риска зависимости от отдельных партнёров нет.

## Методологические заметки

- **customer_id vs customer_unique_id.** В датасете `customer_id` уникален для каждого заказа, а не для человека — RFM-анализ и подсчёт повторных покупок корректны только на `customer_unique_id`. Ошибка на этом уровне даёт ложный вывод «0% повторных покупок».
- **Работа с некорректными типами данных.** Столбец с суммой платежа импортировался как текст из-за locale-конфликта (точка/запятая как разделитель дробной части) — исправлено явным указанием локали при преобразовании типа.
- **Циклические зависимости в модели Power BI.** Одновременное использование двунаправленной фильтрации на нескольких связях создавало циклическую ссылку — решено точечно, через `CROSSFILTER` в конкретных мерах вместо постоянной двунаправленной связи.
- **Абсолютное время доставки vs % опозданий.** Для оценки надёжности продавца абсолютное время доставки вводит в заблуждение (зависит от географии продавца) — использован % опозданий относительно обещанного срока как более честная метрика.
